# 命令行用法

需要 Mac、macOS 13 或更新版本，以及已在本机下载的「信息」短信。源码构建需要 Apple Command Line Tools；测试需要 Swift 6 或更新版本。当前版本在 Apple Silicon、macOS 27.0.1 上完成构建及部分真实号码回归；尚未在其他系统版本或 Intel Mac 上实测。

### 1. 准备黄页模板

从 [vCards 官方 Releases](https://github.com/metowolf/vCards/releases/latest) 下载 `archive.zip` 并解压。先把需要的企业名片导入自己的通讯录，例如启用了同步的 iCloud 账户。可以仅导入自己需要的企业，不必全部导入。

保留解压后的 `.vcf` 目录，扫描时用它限定可匹配的企业。官方的 `default.vcf` 合集也支持。**不要选 GitHub 源码里的 YAML 目录。** 工具只读取模板中的公司名称，不负责导入模板。独立 CardDAV 订阅里的只读名片不能直接修改，需使用自己可编辑的联系人。

### 2. 构建和检查

进入本项目目录，运行。如果拿到的是已经编译好的版本，可以跳过第一行：

```sh
bash scripts/build.sh
./dist/yellowpage demo
./dist/yellowpage doctor
./dist/yellowpage accounts
```

`demo` 用虚构数据展示匹配结果，不读取你的信息或通讯录。`accounts` 列出账户及标识，带 `*` 的是默认账户。

首次实际扫描可能需要：

- 在「系统设置 → 隐私与安全性 → 完全磁盘访问权限」中允许运行工具的终端应用，然后重新打开终端。这用于读取「信息」数据库。
- 在系统的通讯录访问提示中允许完整访问。仅允许部分联系人时，无法可靠检查号码是否已被其他名片使用，工具会停止。

不需要 `sudo`。程序不会自行修改权限、代理或 iCloud 设置。

### 3. 生成预览

下面假设官方模板解压到了 `~/Downloads/archive`：

```sh
./dist/yellowpage scan --vcards "$HOME/Downloads/archive" --out "$HOME/Desktop/黄页预览.json"
./dist/yellowpage review "$HOME/Desktop/黄页预览.json"
```

默认检查本机仍保留的全部收到的 SMS 短信。只想补充某个日期以后出现过的号码，可以指定：

```sh
./dist/yellowpage scan --vcards "$HOME/Downloads/archive" --since 2026-01-01 --out "$HOME/Desktop/黄页预览-2026.json"
```

即使指定日期，工具仍检查该号码在本机更早的短信，防止它曾被多个品牌共用。`--container "账户标识"` 可以指定 `accounts` 列出的账户；否则使用默认账户。扫描输出会明确显示选中了哪个账户。

计划文件不会覆盖已有文件。再次扫描请使用新文件名，或自行删除不需要的旧计划。

### 4. 确认后补充号码

先看清预览里的对应关系，再运行：

```sh
./dist/yellowpage apply "$HOME/Desktop/黄页预览.json" --yes
```

程序重新读取短信和联系人，检查计划是否仍然适用，然后逐张名片追加号码，标签为「短信」。已有号码不重复添加。名片或短信发生相关变化时，会停止并要求重新扫描。

每次操作的电话字段备份和新增记录保存在：

```text
~/Library/Application Support/YellowPage/Runs/
```

命令会打印实际的记录路径和撤销命令。也可以用 `--journal-dir "目录"` 指定保存位置。记录先写入磁盘，再修改该张名片。不会导出完整通讯录、头像或备注。

保存到 iCloud 账户后，后续同步由 macOS 处理。工具不能强制同步，也不能保证其他设备立刻更新显示。

### 5. 撤销一次操作

使用上一步打印的实际记录路径：

```sh
./dist/yellowpage undo "/完整路径/某次操作.journal.json" --yes
```

只移除那次操作新增、且字段标识、号码和标签均未变化的号码。原有号码和之后另行添加的号码会保留。如果名片被合并、移动、改名，或新增号码后来被编辑，工具会停止，交由你核对。重复撤销不会重复删除。

中断或系统报错时，记录中可能出现 `prepared`：表示已经准备写入，但无法确认最终保存状态。这些号码**不会被自动重试或自动撤销**，应按记录人工检查。多张名片的操作不是一个不可分割的事务，前面成功的部分有独立记录。

## 匹配规则

当前只处理 106 开头的号码，接受明确的 `+86` / `0086` 中国区号。普通手机号码、客服短号、邮件地址和 iMessage 不在处理范围内。

| 情况 | 处理 |
| --- | --- |
| 正文以 `【示例银行】` 或 `[示例银行]` 开头 | 提取签名；允许开头空白 |
| 签名、模板公司名称、现有名片公司名称一致 | 可生成追加计划 |
| 大小写、全角半角或空白差异 | 规范化后比较 |
| 简称、繁简体差异、旗下品牌或近似名称 | 不推断归属，跳过 |
| 号码曾出现多个不同签名 | 跳过 |
| 有短信缺少开头签名，或正文解码失败 | 跳过该号码 |
| 本机数据库中存在垃圾信息标记 | 跳过；不清除标记 |
| 同一账户有多张同名公司名片 | 跳过，避免选错 |
| 号码已在其他名片或账户中 | 跳过，不移动号码 |
| 号码已在目标名片中 | 跳过，不重复添加 |
| 模板外企业或通讯录里尚不存在 | 跳过，不新建 |

品牌签名不是身份认证。短信可能伪造签名，平台也可能共用或重新分配号码。工具只能根据本机仍保留的历史发现冲突，无法推断未下载、已经删除或未来的短信。因此写入前仍需要看一遍预览；保存名称也不代表短信内容、链接或来电可信。

## 出现写入错误时

命令行默认通过 Apple 的 Contacts API 保存。图形版默认的「自动方式」会在 macOS 26 及以上通过联系人 App 保存。如果系统返回 `134092` 等保存错误，先看操作记录，核对是否已经添加过部分号码，然后重新扫描。

本版本还提供一个显式的兼容选项，通过「联系人」App 的公开 AppleScript 接口追加号码：

```sh
./dist/yellowpage apply "$HOME/Desktop/重新生成的预览.json" --yes --writer contacts-app
```

它可能请求允许终端控制「联系人」App。先保存或取消联系人 App 里正在编辑的名片，执行期间暂时不要编辑同一张名片。它会核对名片和号码的标识；脚本接口与 Contacts API 看到的内容不一致时停止。使用此方式的操作，撤销时也使用相同接口。

默认方式与兼容方式都不直接修改通讯录数据库，不要求备注的特殊授权。自动化测试覆盖模拟写入和撤销、脚本编译；另在开发机完成部分真实号码的添加与撤销回归。全新账户首次授权、多设备同步及其他系统尚未完成实测，详见[验证说明](../验证说明.md)。

## 数据与隐私

程序不联网，不上传短信或通讯录，不包含分析统计服务。读取 `~/Library/Messages/chat.db` 时使用 SQLite 只读连接和读取快照，且仅处理仍在会话里的收到的 SMS，不修改短信数据库。

预览文件含发送号码、品牌签名、时间、目标名片标识和将要修改的电话字段；操作记录包含撤销所需的电话字段。**不保存短信全文或验证码**。这些文件以仅当前用户可读写的权限创建；公开分享工具时不要附带自己的计划和操作记录。终端输出也可能显示号码和品牌，录屏时可先用 `demo`。

「信息」数据库及正文归档格式不是苹果公开稳定的应用接口。系统更新、短信同步情况或特殊正文格式都可能影响读取；结构不兼容或无法解析时会报错或跳过，不猜测号码归属。

## 开发与验证

无第三方依赖，使用 Swift、Foundation、Contacts、SQLite，以及少量 Objective-C 兼容旧版正文归档。

```sh
bash scripts/test.sh
bash scripts/build.sh
```

测试使用合成 SQLite 短信、虚构名片和内存写入接口，不会修改真实通讯录。覆盖签名解析、日期范围、共用号码、跨账户冲突、原始/归档正文、只读访问、重复执行、变化检测、部分失败记录以及撤销保护。

源码可在 Intel Mac 上自行编译，但本次提供的成品仅为 Apple Silicon。成品为本地临时签名，没有经过 Apple Developer ID 签名或公证；面向公众正式分发前应完成相应发布和兼容性验证。
